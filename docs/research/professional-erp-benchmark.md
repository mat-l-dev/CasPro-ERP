# Benchmark de procesos profesionales

Corte/consulta: 2026-09-11. Investigación de capacidades oficiales; no prueba de una instalación, recomendación de compra ni equivalencia funcional con SAP. El diseño CasPro está en las specs enlazadas desde el [expediente](../evidence/professional-operational-completeness.md). REQUIRED significa requisito confirmado que debe quedar especificado; todas las implementaciones siguen sin autorización. DESIGN NOW IMPLEMENT LATER conserva diseño completo con activación posterior; TRIGGER ONLY exige necesidad nueva; NOT RELEVANT excluye una capacidad del producto actual.

## Cobertura y límites de adopción

| Grupo de requisitos | Resultado profesional adoptado | Clasificación y límite |
|---|---|---|
| 01–04 | Maestros ricos, catálogo por perfiles y conjuntos comerciales; rastrear el compromiso exacto | REQUIRED; departamentos1–4 confirmados;5–6 TRIGGER ONLY para activación, sin módulos nuevos |
| 05–07 | Separar fórmula de valoración, identidad física y movimiento entre sedes/almacenes | REQUIRED; decisión de costo sustentada en [normativa](normative/operational-completeness.md), no en popularidad del método ERP |
| 08–16 | Quote→contrato→orden; crédito controlado; RFQ→award→PO; importación→recepción→costo | REQUIRED para prepago, sourcing/importación; DESIGN NOW IMPLEMENT LATER para crédito/contraentrega bajo D03 |
| 17–20,35–36 | Instrumento, saldo financiero, pago, contabilidad y documento son objetos distintos | REQUIRED frontera; préstamos/tarjetas y alquiler se entregan por incrementos después de primitivas M06 |
| 21–23,33,38–39 | Original, versiones, firma, custodia y exportación con navegación al hecho | REQUIRED por mandato; [proveedor storage](https://supabase.com/docs/guides/platform/backups) confirma que backup DB no copia objetos. No atribuir custodia física/IOFE a los cuatro ERP por falta de evidencia localizada |
| 24–29 | Expedientes fiscales, sistemas electrónicos y conciliaciones por obligación/período | REQUIRED por fuentes SUNAT/CDI; no asumir localización peruana certificada de un vendor |
| 30–32,34 | Perfil cliente/sitio/tarea y reclamaciones con vencimiento y evidencia | REQUIRED diseño acotado; activación por caso y normativa. No inferir ley peruana de un benchmark comercial |
| 37–40 | Aprobación por dueño, imports con preview, trazabilidad y configuración efectiva | REQUIRED; escala por contratos y datos preservados. No GenericWorkflowEngine, GenericTaxDSL ni graph database |
| Expansiones no confirmadas | Servicio vendido independiente, RMA completo, manufacturing, HR/payroll, consolidación/grupos, multicanal | TRIGGER ONLY para un caso empresarial nuevo; NOT RELEVANT para incorporarlos en esta misión |

Las fuentes soportan patrones concretos, no una afirmación de exhaustividad de cada ERP. Sitios/traslados, préstamos/caja chica, firma y compliance se diseñan por el mandato y la evidencia normativa correspondiente; su ausencia en esta muestra no prueba ausencia del producto investigado. El estándar profesional adoptado es una frontera completa de hechos, estados, controles, correcciones y conciliación para cada necesidad conocida, con entrega incremental.
